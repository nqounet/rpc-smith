# 0002 - Echo

目的: 引数（params）を受け取り、そのまま返す `echo` メソッドを実装する。位置引数（配列）と名前付き引数（オブジェクト）の両方をサポートする。

要求例（名前付き）:
```
{"jsonrpc":"2.0","method":"echo","params":{"message":"hi"},"id":"a1"}
```

期待レスポンス:
```
{"jsonrpc":"2.0","result":"hi","id":"a1"}
```

要求例（位置引数）:
```
{"jsonrpc":"2.0","method":"echo","params":["hi"],"id":2}
```

難易度: 超入門

ヒント:
- `params` が配列かオブジェクトかで処理を切り替える。
- 名前付き params の場合はキー `message` を優先的に返すと分かりやすい。

検証:
- 両方の形式でリクエストを投げ、期待通りの値が返るか確認する。

## テスト仕様

- リクエスト（名前付き）:
```
{"jsonrpc":"2.0","method":"echo","params":{"message":"hi"},"id":"a1"}
```
- 期待レスポンス（名前付き）:
```
{"jsonrpc":"2.0","result":"hi","id":"a1"}
```
- リクエスト（位置引数）:
```
{"jsonrpc":"2.0","method":"echo","params":["positional"],"id":2}
```
- 期待レスポンス（位置引数）:
```
{"jsonrpc":"2.0","result":"positional","id":2}
```
- 自動検証のヒント: レスポンスの `result` を比較する簡単なスクリプトまたは `jq` を使う。

## テスト仕様（構造マッチ）

- 検証方針: レスポンスの JSON 構造（必須フィールド・型・主要値）を確認します。文字列表現の完全一致は不要。

- ケース A（名前付き params）必須条件:
	- `.jsonrpc` が `"2.0"`
	- レスポンスに `result` が存在し、値はリクエスト内 `params.message` と等しい
	- `id` はリクエストと一致（`"a1"`）

- jq による例:
```
curl -s -X POST -H "Content-Type: application/json" \
	-d '{"jsonrpc":"2.0","method":"echo","params":{"message":"hi"},"id":"a1"}' \
	http://localhost:4000/rpc | jq -e '.jsonrpc=="2.0" and .id=="a1" and .result=="hi"'
```

- ケース B（位置引数）必須条件:
	- `.jsonrpc` が `"2.0"`
	- `result` が配列の最初の要素に相当する値（ここでは `"positional"`）
	- `id` は `2`

※ 実装によっては `result` に配列を丸ごと返す設計もありうるため、テスト定義に合わせて確認ロジックを柔軟に実装してください。
