# 0003 - Sum

目的: 数値の配列を受け取り合計を返す `sum` メソッドを実装する。

例:
```
{"jsonrpc":"2.0","method":"sum","params":[1,2,3],"id":3}
```

期待レスポンス:
```
{"jsonrpc":"2.0","result":6,"id":3}
```

難易度: 超入門→入門

ヒント:
- `params` が配列であることを確認する。配列要素がすべて数値であることを検証する。
- 不正な型が含まれている場合は JSON‑RPC のエラー（例: `-32602` Invalid params）で応答する。

検証:
- 正常系と不正な入力（文字列やオブジェクトが混入）を送ってエラー処理を確認する。

## テスト仕様

- 正常リクエスト:
```
{"jsonrpc":"2.0","method":"sum","params":[1,2,3],"id":3}
```
- 期待レスポンス:
```
{"jsonrpc":"2.0","result":6,"id":3}
```
- 不正リクエスト（型エラー）:
```
{"jsonrpc":"2.0","method":"sum","params":[1,"x",3],"id":3}
```
- 期待エラー（例）:
```
{"jsonrpc":"2.0","error":{"code":-32602,"message":"Invalid params: all elements must be numbers"},"id":3}
```

## テスト仕様（構造マッチ）

- 正常系必須条件:
	- レスポンスの `.jsonrpc` が `"2.0"`
	- `.result` が数値で値が `6`
	- `.id` が `3`

- 型エラー（不正パラメータ）必須条件:
	- レスポンスに `error` オブジェクトが存在すること
	- `error.code` が `-32602`（Invalid params）など適切なコードであること
	- `id` はリクエストの `id`（ここでは `3`）をエコーしていること

- jq による成功チェック例:
```
curl -s -X POST -H "Content-Type: application/json" -d '{"jsonrpc":"2.0","method":"sum","params":[1,2,3],"id":3}' http://localhost:4000/rpc | jq -e '.jsonrpc=="2.0" and (.result|type)=="number" and .result==6 and .id==3'
```
